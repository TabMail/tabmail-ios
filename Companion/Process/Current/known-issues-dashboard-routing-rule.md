# Known-issues dashboard routing rule

> Routed from `CLAUDE.md` on 2026-08-13 to keep mandatory startup context within budget. The paragraph below is preserved verbatim; `CLAUDE.md` retains the mandatory keyword-bearing pointer.

**⚠️ `KNOWN_ISSUES.md` IS A FILTERED DASHBOARD, NOT THE REGISTER — never conclude from it that an issue is unregistered.** It is **generated** by `Scripts/compact_known_issues.rb` (hand edits to its body break `verify` byte-for-byte, exit 1) and `EXECUTIVE_DISPOSITIONS = %w[open accepted]` emits **only** those two dispositions. So ~123 of 140 register rows — every `closed-decision`, `fixed`, `attribution-first`, `not-defect`, `decomposed`, `historical` row — **have no line in it by design**, as its own census sentence states. **The register is `Companion/Process/Current/KnownIssues/`; search THERE, per the routing protocol, before claiming anything is unregistered or re-opening settled work.** Cost of skipping this, 2026-08-13: `IOS-LOG-001/-002/-003` are closed decisions covering ~1,619 pre-existing ungated `print(` sites, explicitly *"registered rather than swept"* and *"do not re-open it as a task"*; a census that never reached `Companion/` sized a sweep at "~38 sites" and dispatched an agent against a corpus 43× larger that a closed decision says to leave alone.
