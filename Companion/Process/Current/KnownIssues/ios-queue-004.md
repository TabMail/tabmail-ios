## Full detail

**`DrainContext.evidenceRefused`'s doc comment claims the surviving refusals *"are raised BEFORE any wire mutation, so the bound is now about round trips rather than duplicates"*. Both halves are false at the tip.** `ProviderEvidenceUnavailable` has exactly **three** conformers (`IMAPProvider.IMAPDestinationEpochRefusal`, `IMAPProvider.IMAPEpochEvidenceMissing`, `IMAPProvider.IMAPLivenessProbeInconclusive`) and **five** reachable refusal sites in `IMAPProvider.move`; only ONE of the five is pre-mutation. (a) `IMAPDestinationEpochRefusal.unknownAtProbe` is raised at the destination probe, before the COPY — the doc is right about this one. (b) `IMAPDestinationEpochRefusal.movedAcrossCopy` is raised from the `catch` around the destination-epoch comparison, whose whole input is the server's `COPYUID` response — it cannot exist before the `UID COPY` has been executed and committed. (c) `IMAPLivenessProbeInconclusive.unparsedUid(folder:requested:)` is thrown from `IMAPProvider.liveSourceUIDs`, which `move` calls ONLY on the `copyProvenUIDs.count != sourceUIDs.count` arm — i.e. after the `UID COPY`, by construction. (d) `IMAPEpochEvidenceMissing` (from `requireUidValidity`, either `unknownLiveEpoch` on a zero SELECT epoch or `unknownAdmittedEpoch` on a zero admitted epoch) at assertion **A4**, which sits after the COPY and after the liveness probe. (e) the same type at assertion **A5**, which sits after the COPY *and* after the `\Deleted` STORE. A minor fifth counterexample: at **A3** the same type is reachable after the INBOX-only legacy `tm_*` flag-strip STORE, though that strip is idempotent and reversible. **The strongest evidence that the comment is stale is inside the tree it describes:** `IMAPLivenessProbeInconclusive`'s own doc comment states that the refusal *"is raised AFTER the `UID COPY`, so bounding the op to one attempt per drain bounds the destination duplicates a re-attempt would seat"* — the exact opposite of the `evidenceRefused` paragraph, in the same repository, landed in the same session. **Concrete reachability:** a UIDPLUS-advertising IMAP server whose SELECT stops reporting `UIDVALIDITY` (SwiftMail defaults `Mailbox.Selection.uidValidity` to `UIDValidity(0)`, which `requireUidValidity`'s `live > 0` guard turns into `unknownLiveEpoch`) between the COPY and A4. The op has already copied to the destination, is requeued by the `error is ProviderEvidenceUnavailable` arm, is skipped for the rest of THIS drain by `evidenceRefused` — and re-attempted on the next drain, where the COPY runs again and seats another destination copy. So `evidenceRefused` is still doing exactly the duplicate-bounding job the comment says it no longer needs to do, which is `IOS-IMAP-006` below. **No behaviour change is proposed:** the skip is correct, the `.haltLane` disposition is correct, and the comment's own closing sentence (*"a future producer may again refuse post-mutation"*) is the right instinct — it is merely already true, twice over. **Attribution — class A, in two increments.** The paragraph was written by `ede315ed8`, whose deletion of `IMAPMoveEvidenceUnavailable.noCopyUidEvidence` it describes; the surviving producers it enumerates were not re-checked against the A4/A5 sites that stand in the same function. `8b7e7044c` then added the third conformer, so the paragraph's *"the surviving producers — the destination-epoch and source-epoch refusals"* no longer even enumerates the conformer set. ⚠️ **CENSUS CORRECTED AT APPLY TIME, and the correction is recorded rather than silently applied.** This row was drafted and verified at `2d85b8729`, where it read *"exactly two conformers … and four reachable refusal sites … only ONE of the four is pre-mutation"*. `8b7e7044c` landed between drafting and application, and the re-grep before pasting found the third conformer, so the counts above are the re-verified ones.
