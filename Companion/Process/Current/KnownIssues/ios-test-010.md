## Full detail

**`drainWriteQueue()` is a barrier for the QUEUE, not a precondition for a `registerGestureIntent` gesture, and its doc comment says the stronger thing.** `registerGestureIntent` is `nonisolated` and synchronous and ends by spawning `Task { await self.enqueueWrite { await self.executeIntentCycle(id: id) } }`; the test barrier is itself `Task { await AccountManager.shared.enqueueWrite { cont.resume() } }`. **Two unstructured tasks then race to the actor**, so the barrier can be appended FIRST and resume on an empty queue while the gesture's own write is still un-enqueued. The helper's doc — *"every write enqueued before this call has drained"* — is TRUE of the queue and FALSE of the precondition a caller reads it as. **Census, with the predicate:** `rg -n 'await drainWriteQueue\(\)' -g '*.swift' .` returns **39** call sites across four suites (`InboxGestureActionTests`, `SearchLocalResultIdentityTests`, `SearchRemoteResultIdentityTests`, `CoordinatedToolActionTests`); `rg -n 'drainWriteQueue'` returns 47, the difference being the **4** definitions and **4** prose mentions — count the `await` form, not the bare symbol. The EXPOSED subset is narrower still: only those asserting durable state immediately after a `registerGestureIntent`-shaped gesture. **Why production is NOT changed.** Making `registerGestureIntent` enqueue synchronously means either converting the actor-isolated `writeQueue` to a nonisolated `Mutex` or making the method `async` — but it is deliberately `nonisolated` and synchronous precisely so MainActor gesture paths need no suspension, which is what makes the swipe feel instant (ADR-IOS-001). **The gesture→durable-write window is inherent to optimistic UI, not a defect in it**, and closing it in the product to make a test helper's doc comment true is the tail wagging the dog. **Recoverability:** nothing user-facing is at stake at all — this is a test-timing residual, not a product path; the durable write still lands, just not necessarily before an unrelated barrier returns. **The sanctioned harness-side strengthening, if a suite ever proves flaky on this:** wait on a **monotone, gesture-owned** condition BEFORE the barrier — `AccountManager.shared.overlayOpRefCountForTesting()[id] == nil` or `pendingIntentCyclesForTesting()[id] == nil` — then take the FIFO barrier as today. Do NOT add a sleep, a retry, or a loosened assertion. **This was the next lever after the suite-trait fix that closed task #91** — `InboxViewModelInsertUndoneTests` was declared `.serialized` but not `.processGlobalState`, so it swapped `AppDatabase.shared` outside the cross-suite lock and a victim suite's `markRead` could `UPDATE` the wrong fixture; the trait was added in this same round. **This lever was deliberately NOT pulled pre-emptively**, because that flake was proven to be the missing trait and not this window.
