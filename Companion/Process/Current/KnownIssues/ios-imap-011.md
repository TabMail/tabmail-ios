## Full detail

**What the user observes:** on a plain IMAP account, a self-sent message exists as two rows — one in INBOX and one in Sent — sharing an RFC 822 Message-ID. Marking the INBOX copy read no longer marks the Sent copy read in the same gesture, and the Sent folder's `unreadCount` no longer moves with it. Shipped `v1.6.38` DID flip both. **Why:** `AccountManager.expandWithSiblingsByRfc822` was REMOVED by `065a827ca` ("Bind ordinary IMAP actions to UID epochs") as a deliberate **D4 SUBTRACT** — the plan records it as *"⚑ NO REFERENCE — INVENTED: remove `expandWithSiblingsByRfc822` from ordinary IMAP"*. It had **3 production + 8 test** hits at `07a4bb703` and has **no declaration anywhere in the tree** at `1d1557187`. `markRead`/`markUnread` now group only the rows the user actually gestured on and admit each group through `admittedOrdinaryActionTargets`, keying the `PendingOperation` by `admission.providerIds` — the provider's NATIVE address — under a proven `observedUidValidity`. **⚠️ Do NOT write that "sync reconciles it."** That phrasing was proposed and is REFUSED: we no longer issue the sibling `STORE`, so there is no server-side flag change for a later sync to observe. The Sent copy simply stays unread until the user acts on it. **(a) Defect — none; this is a capability deliberately removed.** Two same-RFC rows in different folders are **different messages**, and expanding a mutation across them by RFC is exactly what D4 bans (ADR-IOS-068 clause 2: *"The RFC 822 Message-ID is never consulted to select or authorize a mutation target on any provider"*). The fan-out it enabled is the shipped defect `IOS-IMAP-002`, where one swipe mutated EVERY copy. **(b) Reachability:** any self-send, or any message delivered to two aliases, on IMAP/iCloud. Common. **(c) Attribution: CANDIDATE-INTRODUCED by `065a827ca`, deliberately.** Shipped behaviour differed and was less safe. **(d) Recovery — and this is NOT a dropped intention.** The user's gesture targeted the row they acted on, and it executed exactly there. Nothing is queued and lost; nothing fails closed. The Sent copy is reachable in the Sent folder and one ordinary gesture marks it read. **The non-recovering case was searched for and none exists:** no durable wrong state is written, and the Sent row's unread status is its own true server state rather than a stale local artifact. **(e) Accepted cost:** a two-gesture instead of one-gesture read for self-sent mail on plain IMAP. **Reintroduction is BANNED** — restoring RFC-keyed expansion on any mutation path re-opens `IOS-IMAP-002` and violates D4. **Why this went unregistered:** `IOS-IMAP-002` owns the D4 keying change but does **not** enumerate this removal, and that gap is why two present-tense citations of the dead helper survived the range — a doc comment in `SyncEngineEpochVerify` and, more consequentially, `Companion/Memory/Current/023`, a MANDATORY-READ routed memory that asserted the flip as current behaviour. Both are corrected, as are two test-suite headers (`StatefulGmailActionServerTests`, `StatefulExchangeActionServerTests`) that told the next auditor a system-boundary fan-out proof was still OWED.
