## Full detail

The NSE's separate read-only `GraphAPI` metadata/body helper still interpolates opaque message and attachment ids without strict path-segment encoding. A reserved-character id can make notification enrichment fail closed to a bare notification; it performs no provider mutation, and ordinary main-app sync restores the message surface. The main-app `ExchangeProvider` path class is encoded (`f07229f37`). This is **not** a post-`v1.6.38` regression — the base has it too; changing the NSE helper remains a separately bounded follow-up.

✅ **FIXED by `592f7202f`, "Encode Graph path segments in the shared client; drop its mutators".** **The invariant that now holds:** a Graph id containing `/`, `?`, `#`, `+` or `=` cannot alter the route the request selects. `GraphAPI.graphPathSegmentAllowed` (the RFC 3986 unreserved set) and `GraphAPI.encodedGraphPathSegment(_:)` are the single implementation, applied at `messageMetadata`, `messageFull` and **BOTH** segments of `attachment`. ⚠️ **THE CENSUS WAS FIVE SITES, NOT THE TWO ID KINDS THIS ROW NAMED** — `messageMetadata`, `messageFull`, `attachment` (two segments), `patch` and `move`. **And this row described the helper as "read-only" when it was not:** `GraphAPI.patch` and `GraphAPI.move` were live mutator methods. A census of `GraphAPI.` across the whole tree found **both had ZERO callers on every target**, so they are **DELETED**, and **this surface is now DELIBERATELY read-only — do not "restore" them.** That removes the NSE's entire provider-mutation surface and makes this row's "read-only" description TRUE rather than merely intended: the extension enriches a delivered notification, and every provider mutation in this app goes through the durable `PendingOperation` queue in the main app, which the extension process cannot drain. The note left at the deletion site requires any future reintroduction to encode every id. **The encoder was MOVED DOWN, not duplicated** — `ExchangeProvider` (main-app only) authored it, and `Shared` is linked by the app AND the NSE, so it had to move down for the extension to reach it; the main app's private `graphPathSegmentAllowed` is deleted and its ~25 call sites are behaviourally identical. ⚠️ **THE REMAINING FOUR-LINE WRAPPER IN `ExchangeProvider` IS NOT REDUNDANT — DO NOT DELETE IT.** Lifting the whole throwing helper into `Shared` does not compile: it throws `ProviderError.invalidURL`, and `ProviderError` is declared in `TabMail/Providers/EmailProvider.swift`, which is main-app-only and not visible from `Shared`. The shared helper therefore returns `String?` and each target keeps its own throw; the allowed set and the percent-encoding call exist exactly once and only the error domain is per-target. **A1:** `git show 07a4bb703:Shared/API/GraphAPI.swift` is byte-identical at all five sites and the shipped `ExchangeProvider` contains neither helper — the shipped architecture is NONEXISTENT, not inapplicable, and its raw interpolation is a weakness treated as a floor and not inherited. **Tests pin the INVARIANT, not the mechanism:** they assert the COMPOSED URL STRING that reached the HTTP boundary for all three live helpers including both `attachment` segments — a test asserting merely that an encoder was called would stay green if it were applied to the wrong segment or its result discarded. Red proof: the three live sites reverted to raw interpolation gave 4 failures against 4 passes, with the hostile id `AA/BB?CC#DD+EE=FF` splitting the path, injecting a second query and injecting a fragment, while all three "ordinary id is not escaped" controls stayed GREEN.
