## Full detail

If attachment reconstruction or a provider failure is followed by exhaustion of the existing retrying status write, the exact row can remain `sending` with `sentAt == nil` until `reconcileOutbox()` resets it on the next process launch. The durable message and attachments remain present; no provider send is silently treated as complete. A generic same-process reset cannot safely distinguish the pre-I/O case from the post-I/O/two-generals boundary and could double-send, so this shipped rare edge remains relaunch-recoverable rather than adding another send-state protocol.

✅ **FIXED by `792048ebd`, "Recover a stranded send in-session and stop shadowing the wake target". ⚠️ THE ROW ABOVE UNDERSTATED IT: the edge was not "relaunch-recoverable", it was unrecoverable FOR THE WHOLE SESSION.** `reconcileOutbox()` had exactly ONE trigger — `RootView`'s launch `.task`, via `reconcilePendingOperations()`. A row left `.sending` with `sentAt == nil` is invisible to `drainOutbox` (which selects `.queued` only) and `OutboxView` offers the user no gesture for it (Retry is gated on `.failed`; Outbox Rule 10 forbids discarding a `sending` row). So the user could foreground and background the app all day and the message would never send and never fail — a dropped user intention by the **wedge corollary**, escapable only by a full process relaunch. **The invariant that now holds:** a stranded `.sending`/`sentAt == nil` row becomes claimable again on every foreground, not only on process launch. `reconcileOutboxOnForeground()` is wired to the existing `scenePhase → .active` branch in `RootView`, beside the foreground sync trigger. **The reconciliation logic itself is byte-unchanged** — the new trigger calls `reconcileOutbox()` UNCHANGED — so the `sentAt`-before-delete double-send firewall (Outbox Rule 3) travels with the new trigger exactly as it does with the launch trigger, and a reader must **not** conclude the firewall was re-implemented: a row carrying `sentAt` is finalized or handed to Sent-append recovery, and only `sentAt == nil` rows are reset.
