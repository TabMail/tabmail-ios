## Full detail

The NSE stages a message together with the UIDVALIDITY its fetch observed, and **two projections then discard it**: `StagedMessage.toInboxRow()` and `StagedInboxRow.toMessageHeader()` do not carry `observedUidValidity`, and `insertNewHeaderFromStaging(...)` contains zero occurrences of it. A row whose epoch was **positively proven** is therefore admitted into the main store as "unknown", and the next gesture on it is refused by the very guard that epoch exists to satisfy — the `IOS-EPOCH-001` window, entered on evidence we had and threw away. **Attribution, independently derived and contradicting the brief:** this is *not* verbatim in the shipped release — `git grep -c observedUidValidity 07a4bb703` returns nothing, so the epoch does not exist there at all and cannot be dropped there. `6e9840ed4` ("Refuse NSE staged content whose identity is not positively proven") added the staging column, `NSEMessageMetadata.observedUidValidity` and `StagedMessage.observedUidValidity`, but did not carry the field through the two projections or the insert, and `git merge-base --is-ancestor 6e9840ed4 e8b4f44c5` confirms it predates the candidate band. So: real, not candidate-attributable, and **not** covered by the "shipped and proven adequate" argument.

✅ **FIXED by `ce6fb384c`, "Carry the NSE's proven UIDVALIDITY through the staging projections".** **The invariant that now holds:** a staged row whose epoch the NSE POSITIVELY OBSERVED with its own live SELECT enters the action path carrying that epoch, so the very next gesture on a just-pushed message is admitted on evidence the system already had — instead of being refused by the guard that evidence exists to satisfy. **All THREE projections carry it now**, not two: `NSEDataBridge.StagedMessage.toInboxRow()` (the field did not exist on `StagedInboxRow` at all, so the in-memory ADR-IOS-049 read model could not carry it), `StagedInboxRow.toMessageHeader()` (the header `AccountManager.resolveHeadersForAction` synthesises for a staged-but-not-yet-durable row, which every gesture feeds to the admission predicate), and `NSEDataBridge.insertNewHeaderFromStaging()` (the merge's durable `MessageHeader` write, which set fifteen fields and never this one). **NO NEW SOURCE OF EPOCH TRUTH AND NO MIGRATION** — no probe, no re-derivation, no column. The value is read from the staging row the NSE **already wrote** and normalized through the tree's existing `SyncEngine.knownUidValidity`, which rejects nil **and** the `0` sentinel (RFC 3501 §2.3.1.1 types UIDVALIDITY as `nz-number`, so `0` means "not reported"), so an unknown epoch stays unknown and is never upgraded into a false trust claim. This **finishes** `6e9840ed4`, which added the column and simply did not carry it through; it does not author a new mechanism. **Fail-safe by construction, both halves verified before the change was written:** the refusing comparison already exists and is the same one guarding every other durable path (`admittedOrdinaryActionTargets` admits only on epoch EQUALITY, plus positivity and `messageId == String(uid)`), so a carried epoch can only ever match or disagree — **it can never widen admission, and C3 is untouched**; and the disposal path for a stale epoch already exists (ARM 1 deletes a staged row positively disagreeing with a settled folder epoch, ARM 2 keeps a quarantined row for retry rather than merging it), so no positively-stale value can reach the insert. ⚠️ **ACCEPTED LIMITATION, stated by that commit: this narrows the row on the PUSH side ONLY.** A folder that has never earned an epoch still refuses the gesture — that is the pre-existing `IOS-EPOCH-001` window (T1.3) and it is **unchanged**. The carry supplies the **row's** half of the comparison, not the folder's. Do not read this flip as `IOS-EPOCH-001` having moved. **A BLESSING TEST was re-scoped, not deleted:** `MessageHeaderObservationEpochTests`' *"NSE staged-only headers remain epochless until staged-row epoch validation lands"* asserted precisely the dropped behaviour as expected; it is now *"An unstamped NSE staged row still projects an epochless header"*, keeping the half that is still true — an absence of evidence is never upgraded to proof — with the previous display name and the reason recorded inline.
