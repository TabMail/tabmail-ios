- **Bulk mark-all retained handoff (2026-07-27 thrown-read closure):** `InboxViewModel.markAllAsRead` keeps its normal durable fast path outside the journal, but an exact `.retainedForRetry` subset is synchronously appended as `.isRead(true)` with deliberate `.gesture` origin, per-id read displays, and captured identities before the deterministic bounded-id cursor advances. - **Process-global test isolation (round 53, interim contract until DI):** `TabMailTests/Infrastructure/ProcessGlobalTestState.swift` defines the recursive Swift Testing `TestScoping` trait `.processGlobalState`. A recursive custom trait MUST conform to both `TestTrait` and `SuiteTrait` (plus `TestScoping` here); declaring only `SuiteTrait` with `isRecursive = true` traps in Swift Testing's plan construction when recursion reaches a leaf test, before any test executes. Its one cancellation-safe FIFO async lock spans suites. Re-entrancy uses a task-local owner UUID plus an actor-owned lease count: a nested scope increments the active owner's leases; a child that acquires before its outer scope returns keeps ownership until the child releases; and an inherited token first used after its original lease ended is stale, so it queues/acquires as a new owner instead of bypassing whichever test currently holds the lock. Every suite that replaces `AppDatabase.shared` or mutates `AccountManager.shared`'s provider/recent-completion registries, `UndoService.shared`, the shared intention journal, a real process-wide `UserDefaults`/Keychain key shared with another suite, or a non-keyed static test hook MUST carry `.processGlobalState` (normally alongside `.serialized`, which still only orders tests *inside that suite*). Keyed one-shot hook dictionaries may remain outside only when every test uses a unique key and the suite touches no other listed global. Async teardown of a shared actor hook MUST be awaited before the test body returns; never hide it in `defer { Task { ... } }`, because that unstructured task outlives the trait lease and can clear the next test's state. `ProcessGlobalTestStateTests` pins the nested database-swap ordering, nested-scope re-entrancy, pre-return child-lease ownership, stale inherited-token queuing, and cancellation removal followed by successful FIFO handoff. This is containment, not architecture: dependency injection per `feedback_singleton_test_di` remains the long-term remedy. New global-mutating suites must join the trait immediately rather than adding another suite-local `.serialized` comment.
- **FakeHTTP isolation (round 53):** new or migrated URLProtocol tests use a per-test `FakeHTTP.Scenario`, pass `scenario.session` to the subject, and `defer { scenario.close() }`. Each scenario injects a UUID scope header and owns an independently mutex-protected matcher/call-log box in the protocol registry, so two concurrent tests may register the same method+URL without consuming each other's response or reset. `reset()` and idempotent `close()` affect only that scenario. The static `FakeHTTP.register/reset/makeSession` surface is transitional for the serialized Exchange mock suite only; do not add new callers. `FakeHTTPTests.parallelScenariosAreIsolated` pins concurrent identical requests plus scenario-local logging, reset, and close.

- **HISTORICAL/SUPERSEDED DETAIL — ADR-IOS-059 identity/destination Undo model.** The useful lesson remains that mutable roles/dates/UIDs are not durable identity. The token ledger, recorded-destination resolver, provider-selected keys, receipts, aliases, and full-row restore described in the following audit bullets are rejected by ADR-IOS-060; they are retained only to explain the spiral.
  - **Superseded undo model:** the gesture seeded destination paths, a token ledger survived stack pop, and Undo resolved a provider-selected identity at the recorded destination. This is not the implementation target. V2 uses a universal normalized RFC identity and issues an ordinary inverse command through the global queue.
  - **Why that one comparison is enough:** a row another client re-filed or trashed is not at our destination → not ours (so an undo *cannot* resurrect deleted mail, with no role read); a hard-deleted row has no candidates → nothing fabricated; a self-sent message's Sent copy shares the rfc822 id but sits elsewhere → excluded for free, no exclusion list. Deleted: both probes, `scopedRole`/`capturedDestructiveRole`/`effectiveRole`/`destinationRole`, `supersedingRoles`, `destinationFallback`, all four supersede/unknown-location guards, the exclusion sets, the upsert-under-old-id restore, and the unread delta math (each touched folder is now recounted from truth inside the same transaction). After round 52's exact-row result and bijection additions the file is 1,347 lines; the undo region remains compact at roughly lines 752–1,069.
  - **Deliberately traded away** (all now "drop", all previously guesses): a row another client re-filed is not dragged back; a hard-deleted row is not re-fabricated; an IMAP message with no `Message-ID` cannot be undone; a folder renamed between gesture and undo stops matching the recorded destination (`Folder.id` is path-derived — the same error one level down; a server-derived stable `Folder.id` is the ADR's follow-up).
  - **THE FAILURE MODE TO WATCH:** if you find yourself adding *one more qualifier/scope/dimension* to a lookup to make a case pass — stop. That is the bug, not the fix.
  - **Round-52 test/consumer audit:** stale undo test narratives naming the deleted role probes/guards were rewritten to the recorded-destination contract. The overlay audit found that `actionTag` and its derived `tagSortOrder` were still separated at several in-memory consumers: AI-batch repaint, staged insertion, detail single/array overlay application, `overlayAdjustedSnapshot`, and direct inbox/detail manual-tag or inbox-exit mutations. Every actionTag assignment at those sites now derives `tag?.sortOrder ?? 99`; focused tests pin each path, including the asynchronous detail thread-array refresh. Treat `tagSortOrder` as a materialized derivative that must change atomically with `actionTag`, even for display-only snapshots.
  - **Round-52 undo follow-up:** `undoDestructiveAction` returns the exact restored header keyed by the snapshot's old id. Resolution is bijective in both directions: one destination row per snapshot AND one snapshot per immutable provider key; duplicate snapshots are all refused even if only one row survives. The fold tracks old-id → actual-id separately from the latest restored header per actual id, so every historical alias sees the row's final serially-restored state after successive IMAP re-keys. Later co-bundled tag/flag/move intents therefore survive in both the normal refresh and forced-read-error paths. Refused members return no alias, and same-RFC Sent siblings stay excluded.
  - **Round-52 test-audit traps:** (1) a destination-seed assertion made after `drainWriteQueue()` is vacuous for the seed — the committed move receipt can overwrite an absent gesture-time value and make the test green. Gate the FIFO before the gesture, assert `UndoService.currentAction.destinationPathByAccount` while the move is blocked, then release. (2) A re-key fixture must use `.imap`/`.icloud`; changing a Gmail/Outlook `messageId` and expecting RFC fallback encodes an impossible provider state and fights ADR-IOS-059. (3) Startup queue mocks must model cancellation followed by DB repopulation: cancellation idles old work, but repopulation with pending rows makes the queue busy again; otherwise deadline/cancellation tests never reach their claimed branch.
