
## Action queue coalesces gesture intents to latest-per-field (ADR-IOS-057, 2026-07-10) + overlay call-site audit closed

- **Intent register**: `AccountManager.registerGestureIntent(id:_:)` / `executeIntentCycle(id:)` over `pendingIntentCycles` — first gesture on an id opens a cycle (ONE overlay retain, ONE queued executor); later gestures while queued only update the register + display overlay. Executor consumes the cycle atomically, resolves the header off-main, writes only fields whose target differs from the resolved header's current truth (round-3; identical to the gesture-time baseline for undisturbed cycles — out-of-band writers like markAllAsRead or remote flips get corrected to the user's latest visualized intent). Even-count toggles / tag-back-to-original = clean no-op: zero writes, zero `PendingOperation`s, zero unreadCount/badge churn, zero remote flips (fixes the backgrounded badge-bounce field report). Covers isRead/isFlagged/actionTag; wired from inbox `toggleRead`/`toggleFlag`/`applyManualTag` and detail `toggleRead`/`toggleReadForThread`/`markReadOnOpenIfNeeded`/`applyManualTag`.
- **Ordering invariant**: on a NEW cycle, `retainOverlayEntry` runs BEFORE `registerMutation` — a sibling op's final release in the gap would strip the just-registered intent (same invariant the pre-register gesture paths documented).
- **Call-site audit (PLAN_OVERLAY_CALLSITE_AUDIT.md §1-§2) CLOSED**: every production `removeOverlayEntries` caller converted to retain/release — move family (inbox+detail, single+thread), `UndoService.undo`, tags. Sole remaining production caller is `releaseOverlayEntry`'s zero-count branch. Overlay entry lifetime = union of ALL in-flight ops for the id; the mixed-path refcount bypass (direct removal stripping a refcounted sibling's entry, and the reverse) is dead. Regression tests: `mixedToggleAndArchiveOnSameId` + reverse order.
- **Move/Undo follow-up (2026-08-09):** restored the simple v1.6.38 interaction model without restoring its unsafe RFC Message-ID move-back. Undo pops the exact displayed top action and paints its source overlay before any suspension, then appends the inverse behind earlier local admissions without waiting for provider work. Exact never-sent opposites annihilate. If an IMAP MOVE is already in flight, the latest opposite stays process-local until `COPYUID` supplies the destination UID, then re-enters the same FIFO as an ordinary move; another gesture in either direction coalesces through that FIFO. Process death may drop this convenience intent and sync exposes server truth. No migration, receipt, alias, second queue, or Message-ID mutation lookup. Regression scenarios: `UndoProviderIdentitySafetyTests` and `QueueCoreInvariantTests.newestUndoDoesNotRetargetWhileForwardWriteIsQueued`.
- Batch `markRead(_:)` keeps its own closure (off-screen resolution; one-direction idempotent writes).
- **TB parity**: deliberate divergence — TB addon fire-and-forgets `browser.messages.update` to TB core (no queue/debounce); iOS owns its own IMAP write path, so the coalescing layer lives here (recorded in ADR-IOS-057).
- Tests: `InboxGestureActionTests` now 24 (cancel-out, odd-count-one-write, cycle-consume-then-new-cycle, tag coalescing, mixed-path both orders, undo retain hygiene, strand checks on refcount + register).

### Same-day follow-up (2026-07-10, second session): plan §6 queue/overlay follow-ups resolved

- **Drain lanes are connected components** (`AccountManager.buildLanes`, pure union-find over all member ids): batch [A,B,C] + later single-id op on B now serialize in ONE FIFO lane — the old `messageIds.first` key ran them concurrently on separate IMAP connections (`ProviderWorkQueue` bounded-concurrency, NOT serial). ADR-IOS-018 amendment.
- **`uidResolutionFailed` is transient for non-move/non-tag ops**: capped retry (`SyncConfig.maxUidResolutionRetries`) instead of unconditional "confirmed stale" drop; `executeSingleOp` returns `SingleOpOutcome` and the lane HALTS on any re-queued op — a later op never runs ahead of its unresolved same-lane predecessor. NOTE: the old `DrainQueueIntegrationTests` hand-mirrored drain logic that had drifted from production (one test literally asserted the opposite of shipped behavior) — real-code tests now exist (`AccountManagerQueueDrainTests`, `PendingQueueLaneTests`); the two big `simulateDrainPass` sims in DrainQueueIntegrationTests/ConnectionResilienceTests still model an OLD algorithm (no lanes) — treat with suspicion.
- **Background write-queue flush**: `didEnterBackground` drains `AccountManager.writeQueue` (deadline-bounded) BEFORE `checkpointForDurability`, closing the "checkpoint fsyncs a WAL missing the queued intent cycles" gap; the `wal-durability-checkpoint` bg task also gained its missing expiration handler. **Swift gotcha recorded in code**: `withTaskGroup` CANNOT implement a timeout race — it implicitly awaits all children even after `cancelAll()` (verified empirically); use two unstructured Tasks racing a Mutex-guarded continuation (`awaitWriteQueueDrainOrTimeout`).
- **Agent tools coordinated** (`performCoordinatedRoleMove(ids:role:)`): EmailArchive/EmailDeleteTool now use the gesture lifecycle (retain→register→enqueue→release) with fresh re-resolve INSIDE the queued closure — the pre-confirmation snapshot could go stale across the unbounded confirmation wait and silently reverse a user's later move (worse than the original "overlay bypass" framing). Any future message-mutating agent tool MUST use this helper, not direct archive/delete.
- **actionTag clears on inbox exit in the move's own updateAll** (+ `tagSortOrder=99` sweep sentinel); dead `.removeTag` enqueue deleted; overlay mutations carry `actionTag: .some(nil)` on inbox-leaving moves (9 gesture sites + the tool helper); undo restores the tag via full-row snapshot save. Stale chips were visible in Archive/Trash lists (`MessageRowView`/`TriageRowView` render the tag UNGATED on isInInbox). ADR-IOS-036 amendment.
- **NavigationStore move badge delta split**: source decrement gates on RAW `!dbIsRead`, dest increment on overlay-projected value — one shared boolean was wrong in BOTH directions under coalesced move+read entries (RED-verified characterization).
- **Push-token boot crash**: `didReceiveDeviceToken` gates on `awaitLaunchReady(background: true)` — the token callback can beat the async DB build (EXC_BREAKPOINT on `rawPool` force-unwrap via `reregisterAllDeviceAccounts`, whose only caller is that path).
- Deferred: UID-rekey resolution fallback (phase 2, with move coalescing — use `DurableIdentityLookup`, IMAP-only, null-rfc822 unprotected).
- **Follow-up-session adversarial audit (8 rounds / 16 passes / 17 defects fixed; rounds 7–8 clean)** — headline finds beyond the §6 list: notification-action ARCHIVE/DELETE buttons were silently dead since 2026-05-30 (wrong-column raw SQL + legacy no-op `.archive`/`.delete` op types → `NotificationActionRouter`); the single-message `.move` uidResolutionFailed destination-check misreads "mid-transit behind an earlier queued move" as "confirmed stale" — closed from BOTH entry paths (batch-split now `.haltLane`s the lane; `move()` re-resolves row truth at entry); undo snapshots must be overlay-adjusted (`AccountManager.overlayAdjustedSnapshot` — a still-queued gesture's fields live only in the overlay; 7 producers incl. `SettingsView.archiveOldMessages`); `archive()`/`delete()` resolved the role path from `movable.first`'s account only — cross-account batches mis-filed (now `moveToRoleFolderPerAccount`). RULE for future audits: strand-hygiene (retain/release balance) checks are blind to dropped-intent bugs AND to wrong-VALUE bugs — audit the value flow (what gets written where from which snapshot), not just the resource flow.
