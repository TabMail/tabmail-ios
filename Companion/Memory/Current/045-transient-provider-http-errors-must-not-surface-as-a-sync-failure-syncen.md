
### Transient provider HTTP errors must NOT surface as a sync failure — `SyncEngine.isTransientError` (2026-06-17)
- **Symptom**: a momentary Microsoft Graph `503` on `GET /v1.0/me` during connect flipped the inbox sync-status subtitle to the failed state. Log chain: `[Exchange] HTTP 503 …/me` → `[AccountManager] Connect failed … (non-auth)` → `[Sync] Error: networkError(underlying: HTTPError.networkError(statusCode: 503))` → `[SyncPhaseMut] lastSyncFailed = true`.
- **Root cause**: the surfacing paths reused `SyncEngine.isConnectionError` to decide whether to suppress. But that predicate **deliberately** returns `false` for `ProviderError.networkError` (HTTP 4xx/5xx) — its job is "should we *reconnect*?", and a 503 means the request completed, so the connection is fine (see its doc comment). So a transient 503 was treated as a hard sync failure.
- **Fix**: added `SyncEngine.isTransientError(_:)` (sibling of `isConnectionError`, `SyncEngine.swift`) = `ProviderError.networkError` wrapping HTTP **5xx or 429** (matches both the `HTTPError.networkError(statusCode:)` enum AND the `NSError(domain:"Gmail"/"Exchange", code:)` shape, mirroring `isHttpGoneStatus`). It is intentionally **narrow (HTTP-only)** — it does NOT include connection errors, so offline behavior (which still flips the failed indicator) is unchanged.
  - `InboxViewModel.performSync` catch: a `catch where isTransientError` arm leaves `lastSyncFailed` untouched and shows no error banner (the reported path — one account's transient throw was aborting the whole multi-account refresh).
  - `AccountManager.foregroundSyncOne` catch: transient → `SyncResult(failed: false)` so the foreground poll doesn't flip the subtitle either. (`foregroundSyncAll` already masked single-account failures via its all-accounts-failed aggregation; this also covers a full-Graph-outage where every account 503s.)
- Tests: `IsTransientErrorTests` in `ErrorClassificationTests.swift`. NOTE the layering — `isConnectionError` (transport/reconnect) vs `isTransientError` (retryable HTTP, don't-surface) vs `isHttpGoneStatus`/`isMessageNotFoundError` (permanent 404/410, drop-the-op) are three DISTINCT classifiers; don't collapse them.
