
### FTS Tokenizer — NO tokenchars (ADR-024, 2026-06-09, lockstep with Rust crate)
- `SearchConfig.ftsTokenize` (mirrors `config.rs FTS_TOKENIZE`) has **no tokenchars**. unicode61 treats all non-alphanumeric characters as separators by default; the old `tokenchars '-_.@'` made those four token-internal, gluing addresses into single tokens that could only be prefix-matched from the token start — root cause of the email-address search bug. Without it, addresses index as parts and any part is matchable ("dmarc" finds `noreply-dmarc-support@…`).
- **Tokenizer changes migrate IN PLACE, invisibly** — `SearchIndex.rebuildStaleTokenizerShards(deadline:)` detects stale shards from their CREATE statement in sqlite_master (currently: contains "tokenchars"), rebuilds each via rowid-preserving `INSERT..SELECT` + rename swap in one transaction, newest year first. No UI. Entry points (reentrancy-guarded, all AFTER sync work so push/sync is never starved): post-init background Task (primary, unbounded); BGProcessing after `syncStartup` (unbounded — minutes of budget); BGAppRefresh and silent-push main path after their sync with a small slice (`SearchConfig.retokenizeShortWindowBudgetSec`). `Task.isCancelled` checked between shards so expiration/deadline races wind down at a shard boundary; pending shards count as "work" in the BG reschedule condition (`hasStaleTokenizerShards`). Stateless detection makes it idempotent/resumable: kill mid-shard → rollback + redo, kill between shards → converted shards stay done. Concurrent writes are a non-issue: each conversion is one serialized-writer transaction, old/new tables share the column list (only `tokenize=` differs), and FTS5 stores text — tokens are re-derived on insert. On TB the same runs host-side inside init under a 45s budget — **NEVER bump the crate's `SCHEMA_VERSION` for this** (the addon treats that as "full re-index from Thunderbird", hours on big archives; see ADR-024).
- `SearchQueryParser.buildFTSMatch` auto-quotes tokens containing `- @ . : +` as prefix queries (`"..."*`) — under the splitting tokenizer these become adjacency-phrase prefixes (correct for partial AND full addresses). `extractColumnScopeFilter` (and Rust `extract_column_scope_filter`) consume the trailing `*` after quoted field values.
- `MemoryIndex` shares the tokenize string via `SearchConfig.ftsTokenize`; memory.db is derived, so its `schemaVersion` bump (v4) drop-and-rebuilds it (Stage A refills).
