
### Raw NIO error types must be added to `isConnectionError` by NSError DOMAIN, not substring (2026-07-04)
- **Leak class**: SwiftMail occasionally lets raw Swift NIO transport errors escape its `IMAPError` wrapping. Their `localizedDescription` bridges to the useless "The operation couldn't be completed. (NIOCore.<Type> error N.)" form, and if `SyncEngine.isConnectionError` doesn't classify them, `InboxViewModel.performSync`'s catch (`InboxViewModel.swift:~1535`) publishes that text verbatim to `viewModel.error` → the (debug-gated, `InboxView.swift:198`) inbox banner, and flips `lastSyncFailed` as a "real" failure instead of a connection blip.
- **Instances so far**: `NIOCore.ChannelError` (fixed earlier, `SyncEngine.swift` domain check) and `NIOCore.IOError` (raw syscall errno failure; banner showed "(NIOCore.IOError error 1.)" during a foreground poll — fixed 2026-07-04, same pattern).
- **Why domain check**: an `IOError` description embeds arbitrary `strerror` text ("Operation not permitted (errno: 1)", etc.) — unenumerable by substrings; NIO structs always bridge with NSError `code 1`, `domain = "NIOCore.IOError"`. Substring `"NIOCore.IOError"` also added for the already-bridged-to-string form.
- **If another NIO type leaks** (`NIOPosix.*`, `NIOSSL.*`…): add its NSError domain check + bridged-string substring to `isConnectionError` and the mirrored test pair in `IsConnectionErrorTests` (`ErrorClassificationTests.swift`), following the ChannelError/IOError precedent.
- The banner path uses raw `error.localizedDescription`, NOT `Error.userFacingDescription` (`Helpers/ErrorFormatting.swift`, which strips the "(Domain error N.)" tail in production) — classification is the correctness layer here, not formatting.
