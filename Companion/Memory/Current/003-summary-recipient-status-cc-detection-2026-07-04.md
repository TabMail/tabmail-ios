
## Summary `recipient_status` (cc detection) — 2026-07-04

Summary requests send `recipient_status: "cc"` ONLY on positive evidence: the **receiving account's** address literally in the Cc header (and not in To, and user not the author). User in neither To nor Cc (alias/plus/Bcc/list delivery) → field omitted — never claim cc when unsure (SMTP envelope is discarded at delivery, so not-in-To proves nothing). Matching asymmetry: suppress checks (author/To) strip plus-tags (loose); the Cc claim is strict exact-address. Backend injects an explicit "only Cc'd" message on `"cc"`. Classification: `PromptVariables.classifyRecipientStatus(toField:ccField:fromField:userEmails:)` (Shared — regex-extracts ALL addresses from raw header strings, parity clone of TB `senderFilter.classifyRecipientStatus`; TB is reference per ADR-IOS-008). Plumbing: optional `recipientStatus` param on `summaryVariables` / `AIService.generateSummary` / `AIService.process`. Computed at 3 sites: `ActiveAIQueue.executeSummaryJob` + `AccountManagerAI.processMessage` (pass `message.to/cc/fromAddress` + `[account.emailAddress]`), NSE `NotificationService` (passes `msg.to/cc/senderEmail` + `[accountEmail]` from the push payload). Verification logs: debug-gated `[AIService] Summary payload: … recipient_status=…("cc" SENT / omitted)`; NSE `step6a … (recipient_status=…)`. Tests: `TabMailTests/Shared/PromptVariablesTests.swift`.

---

**Update 2026-10-10 (iOS #214, merge `bbdfc4cd`):** the Cc claim no longer regex-extracts addresses. Stored address fields are written escaped (`IMAPFetchMapping.mailboxText`: quoted-pairs per Unicode scalar, CR/LF as a space; invalid ENVELOPE text always quoted), and the claim, reply-all and `MessageViewHelpers.extractNames` all read them with SwiftMail's `AddressParser`. A crafted display name can no longer create a claim or a reply-all recipient; the 2026-07-05 accepted residual is resolved on iOS (owner reversed it 2026-10-09). The suppress path (From, To) still uses liberal extraction, which can only omit. Owner-accepted scope: rows stored before #214 keep their old text until re-synced; Thunderbird keeps its own scanner and differs only on malformed or crafted text.
