
### Stuck-`isLoading` rule: async view loads must defer-clear their spinner flag — and `.task` must NOT hang on the conditional it flips

- **`.task`-on-conditional self-cancellation (Account page infinite spinner, root-caused on-device 2026-07-08):** attaching `.task { await load() }` (or `.onAppear`) directly to a `@ViewBuilder` conditional (`if isLoading { spinner } else if errorMessage { … } else { content }`) is a footgun: every branch flip fires disappear/appear on the conditional, cancelling and RESTARTING the plain `.task` — and the load's own state writes flip the branch (`isLoading = true` on entry, `isLoading = false`/`errorMessage` on exit). Observed as a ~100Hz self-sustaining cancel/restart storm (`URLError.cancelled` instantly, `cancelled=true`, view identity STABLE — same `[Dashboard] id=`, appear+disappear each cycle). With the old happy-path-only clear it instead deadlocked silently: first success flipped the branch → task restarted → cancelled itself → `isLoading` stranded true → permanent spinner, zero logs. **Fix + rule:** hang `.task`/lifecycle modifiers on a stable wrapper (`ZStack { content }`) that survives branch flips; see `AccountDashboardView.body`. Full narrative in the ADR-IOS-054 amendment.
- **The defer half of the bug class (bitten twice now):** a `.task`-driven load that clears its spinner flag only on the happy path (`if !Task.isCancelled { isLoading = false }`, or no clear at all on early returns) strands the view on a forever-spinner when the task is cancelled — and cancellation paths are typically the SILENT ones (no logs). Instances: `InboxViewModel.performSync`/`isRefreshing` (fixed 2026-06-15, above) and `AccountDashboardView.loadData`/`isLoading` (fixed 2026-07-08).
- **The rule:** clear the flag in a `defer`, decide what to SHOW based on what data actually arrived (e.g. set an `errorMessage` + Retry when a cancelled load produced nothing), and give every cancellation catch a debug-gated trace so the silent path is never silent in debug builds.
- **Codebase sweep (2026-07-08, all 45 `.task` sites):** 4 true positives fixed with the same stable-anchor treatment — `RootView.body` (all four `.task(id:)`s hung on the unwrapped `routedContent` conditional; two write its branch vars `isCheckingConsent`/`isStartupComplete`), `TemplateMarketplaceView`, `MySharedTemplatesView` (both had `.task` on a `Group`-wrapped `isLoading` conditional). **`Group` does NOT stabilize — it's a transparent pass-through; `ZStack`/`VStack`/`List`/`Form`/`NavigationSplitView` do.** Remaining borderline sites (one-directional or terminal flips, no oscillation risk, left as-is): `TabMailApp.swift:337` splash, `MailNavigationView` ServerDraftComposeLoader, `ChatHistoryView`, `ReminderTopCard`, `SummaryBubbleView` timeout failsafe, `PlanPickerView` products-empty arm, `RootView:105` demo seeding (terminal exit-on-error).
- **Extra hardening on AccountDashboardView only:** the collapsed-split-view navigation transition fires ONE spurious disappear on a freshly-appeared content-column page (onAppear → onDisappear, view still visible, no re-appear) — enough to cancel even a stably-anchored structured `.task` mid-fetch once. Its initial load therefore runs on an UNSTRUCTURED `Task` with a `loadInFlight` dedup guard. Apply the same treatment to other content-column pages only if their logs ever show the one-shot `CANCELLED (URLError.cancelled)` signature.
- `AccountDashboardView` diagnostics: `[Dashboard] loadData START/exit id=… cancelled=… hasInfo=…`, `[Dashboard] onAppear/onDisappear id=…` (per-identity instance id distinguishes remount loops from task restarts), `[Dashboard] fetch… CANCELLED` (all debug-gated); navigation traces `[NavAccount] navigateToAccount → push` and `[NavAccount] selection changed old → new` in `MailNavigationView`.
- Reminder: `InboxView.body`'s modifier chain is AT the Swift type-checker budget — even ONE more `.onReceive` or `.modifier()` entry fails the build with "unable to type-check this expression in reasonable time." New notification listeners must merge into an existing extracted `ViewModifier` (see `CollapseChatOnNavigateModifier` — template-pill + navigate-to-account merged into one publisher — or `StagedRowsReceiver`) rather than adding chain entries.
