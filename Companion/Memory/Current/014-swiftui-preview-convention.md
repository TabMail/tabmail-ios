
### SwiftUI preview convention

- **All `#Preview`s live in `TabMail/Views/Previews/<Group>/<View>+Preview.swift`, wrapped in `#if DEBUG`** — NOT inline in the view file. Groups are feature-area folders: `Account`, `Agent`, `App`, `Components`, `Compose`, `Consents`, `Demo`, `Inbox`, `Tooltips`. XcodeGen globs `TabMail/` recursively, so a new group folder is auto-picked-up (just rerun `./Scripts/xcodegen.sh`).
- **`PreviewMocks` (`Views/Previews/PreviewMocks.swift`) is the shared factory** for rendering REAL host views (not stand-in mocks): `bootstrapAppDatabase()` (ephemeral on-disk WAL pool), `seedInbox()` (1 account / 1 inbox / 5 fully-classified messages w/ tags+summaries+replies), `seedOutbox(account:)`, `navigationStore()` (real `loadInitialData()` + opens `AISubscriptionGate`), and `spotlight(_:)` for isolating one TipKit tip, and `hideAllTips()` for host-view previews that shouldn't show ANY tip (else tooltips pop in on interaction — Xcode reuses the preview process so a prior `spotlight` leaks). To show a real `InboxView`: `NavigationStack(path: .constant([scenario.inbox]))` + `.navigationDestination(for: Folder.self)` → `InboxView(...)`, `.environment(navStore)` + `.environment(\.hasTabMailSession, true)`. Pattern reference: `EnableInboxPushTip+Preview.swift`. To make a banner/notification-driven nav testable in the canvas, host the seeded view in a `NavigationStack` and bridge its notifications to a `path` push (reference: `UsageThrottleBanner+Preview.swift` — also injects a fresh `StoreKitManager` for `PlanPickerView`).
- For state that gates a view (subscription, throttle, etc.), add a `#if DEBUG` preview-only setter on the relevant `@Observable` store (e.g. `UsageThrottleStore.previewConfigure`) rather than constructing a full backend response.
