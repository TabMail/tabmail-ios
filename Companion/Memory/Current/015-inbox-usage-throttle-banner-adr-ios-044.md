
### Inbox usage-throttle banner (ADR-IOS-044)

- **`AccountInfo.queueMode` / `quotaPercentage` / `planTier` from `/whoami` are the proactive throttle signal** (the 429 `.throttled` SSE events only flow through the chat path `sendCompletionsWithTools`; the background summary/action path `sendCompletions` has NO throttle callback). `UsageThrottleStore` (`Services/AI/UsageThrottleStore.swift`, `@Observable` singleton) caches them + `hasOwnAPIKeys` (`AIService.shared.byokBundle != nil`) and exposes `banner: UsageThrottleBannerKind?`.
- **Fed from the existing always-on foreground whoami** in `RootView.revalidateAISubscriptionGate()` (launch-`.active` + sign-in) + `AccountDashboardView.fetchAll`; `refreshKeyState()` from `APIKeysView` key persist. NO new poll. `hasCheckedOnce` is in-memory → no cold-launch flash.
- **Tier branch:** Basic+throttled → upgrade-to-Pro (`PlanPickerView`); BYOK+no-key → TabMail Settings' **AI Provider** section (provider picker per tier + Manage API Keys — NOT the raw keys page, since BYOK needs both); Pro → nil (placeholder for Max/pay-as-you-go). `UsageThrottleBanner` (`Views/Shared/`) is subtle, no dismiss button, inbox-only (`isInboxView`). Preview renders the REAL `InboxView` (`Views/Previews/Inbox/UsageThrottleBanner+Preview.swift`) via `PreviewMocks.seedInbox/navigationStore` + `UsageThrottleStore.previewConfigure` (DEBUG-only) — see "SwiftUI preview convention" below.
- **Navigation:** `.navigateToPlanPicker` → `selection = .planPicker`. `.navigateToAIProvider` → set `TabMailSettingsView.pendingScrollAIProviderKey` (UserDefaults) + `selection = .prompts`; `TabMailSettingsView` is wrapped in a `ScrollViewReader` and scrolls (on appear) to the `.id`-anchored AI Provider section, then clears the flag. NO standalone provider/keys `MailboxSelection` route — provider selection only exists inside TabMail Settings. The nav `.onReceive`s live in the `NavigationNotificationHandlers` ViewModifier — keeping them inline blows the `body` type-check budget.
