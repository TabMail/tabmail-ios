
### A bridged `NSError` code is never an HTTP status: read it through `httpStatus(of:)` (2026-11-09, #480)
- **Trap**: Gmail and Outlook requests throw `ProviderError.networkError(underlying: HTTPError.networkError(statusCode:))`. A Swift error enum bridged to `NSError` gets a case index as its code (Swift numbers the cases with payloads first, then the rest, so `ProviderError.notConnected`, declared first, bridges to 7; `HTTPError.networkError` bridges to 1, `networkErrorWithBody` to 2, `invalidURL` to 0, and `ProviderError.networkError(...)` itself to 0), so `catch let error as NSError where error.code == 409` or `(error as NSError).code == 404` on the thrown error never matches, and the branch is dead.
- **Instances**: `AccountManager.syncFolders(_:)` (a gone label or folder ended the account's folder loop, cancelled the other accounts' sync and raised the error banner) and `UserLabelMenuModel.createAndApply(name:)` (Gmail's 409 for a label name it already has was never recovered, so the gesture failed silently). Both fixed in #480.
- **Rule**: read a provider HTTP status only through `httpStatus(of:)` in `EmailProvider.swift` (it unwraps `ProviderError.networkError`, matches `HTTPError.networkError(statusCode:)` structurally, and otherwise falls back to the underlying error's bridged `NSError` code). That fallback is a status only for the `NSError(domain: "Gmail"/"Exchange", code: status)` shape the draft-delete and trash paths throw; for any other underlying error it is a case index (`networkErrorWithBody` gives 2, `invalidURL` 0) or a negative `URLError` code, so compare the result only against the 4xx/5xx statuses you mean. `isHttpGoneStatus` is built on it.
- **Making a dead branch live**: check what it reaches. The 409 arm now keeps Gmail's spelling of the name (the lookup compares without case) and replaces a menu entry with the same id instead of listing the label twice.
- **Census** (the issue #480 comment): every other status check either matches the error structurally (`SyncEngine.isTransientError`, `AccountOperationExecutor.isMessageNotFoundError` / `isConfirmedGoneError`, `ProviderMemberAbsence.isAuthoritative`) or reads `HTTPURLResponse.statusCode` / a typed calendar or backend error.
