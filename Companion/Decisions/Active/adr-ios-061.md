## ADR-IOS-061: UIDVALIDITY Reset Closure — Detect Everywhere, Refuse at the Provider, Purge-and-Resync the Folder

**Context:** The 2026-07-15 family audit ("a message referenced by a MUTABLE key across a time gap") kept finding variants of one root cause: for IMAP, the UID is the local ADDRESS (row id = `accountId:folderPath:UID`, sync windows by UID per ADR-IOS-042) while the RFC Message-ID is the IDENTITY — and a UIDVALIDITY epoch change silently invalidates every address while the code kept treating addresses as identity across the boundary. Point fixes (Rounds 2b/2c/2d) each closed one seam and the next audit found the seam one layer further (fold→action-txn TOCTOU, body fetch, in-place rfc rewrite by sync, `lastKnownUidValidity` never advancing after a real reset — so the claim-time check could never fire for one, and never-walked folders failed open entirely). RFC 3501's contract is total: a UIDVALIDITY change voids every cached fact about the mailbox.

**Decision (owner-directed, 2026-07-15):** treat the epoch as first-class, and respond to a change the way the protocol means it — void the folder and sync from scratch, "as if we re-add an account." Four composing pieces, staged as commits `beab3a1` (Stage 1), `0ddfde0` (Stage 2), `29dd45e` (Stage 3), Stage 4 (riders + this entry):

1. **Epoch ledger (§2, v75/v76):** `Folder.lastKnownUidValidity` is maintained truth — recorded from EVERY SELECT (all 25 `selectMailbox` sites route through one tracked helper; STATUS responses feed it too) into the row plus a synchronous Mutex mirror. A CHANGED observation never overwrites the stored value (the ledger must describe the rows actually in GRDB until the reaction purges); it fires the reaction instead. New columns: `uidValidityResetPendingAt` (v75, the quarantine/re-drive flag) and `lastUidValidityResetAt` (v76, the reset moment, consumed by the NSE merge epoch guard).
2. **Provider refusal (§3):** every UID-addressed IMAP op compares the live SELECT epoch against the mirror and throws typed `ProviderError.uidValidityChanged` (never string-matched) instead of executing. ADDITIVE to the v74 admission-stamp slot — the slot is KEPT (re-keyed `(accountId, folderPath)`, zombie-reaper compare-and-clear) because the drain path must compare against the op's own ADMISSION-era stamp: the reaction's own stamp write is exactly the sync write that would race a ledger-only compare. **Queue semantics (owner rule): demote, never drop** — the refusal proves the ATTEMPT can't proceed, not that the intention is stale; RFC members retry into the new epoch by Message-ID SEARCH (epoch-immune), token-tail members die at the existing claim-time stamp check once the ledger advances (degraded-tail, owner-accepted). A quarantined folder demotes at claim with ZERO provider calls — the UNION of member-intersection chains (spans folders; a folder-filtered demotion would reorder same-member ops), one gated write, flag re-read in-txn.
3. **Reaction (§4):** single-flight per (account, folder) with record-while-held; trigger validation against CURRENT stored state (no trusted payloads); suspension-bracketed, abort-leaves-flag-set, durable-flag re-drive owned by fullSync's per-folder loop (a flagged folder BRANCHES INTO the reaction — never a plain skip), re-entering at the journal barrier. Steps: arm flag → drain the intention journal (bounded; exhaustion ABORTS — never purge over an undrained journal; this is what makes the purge never-drop-safe: every pre-purge gesture folds to a durable op first) → one gated purge txn (headers by folderId + cascades, pendingRender, chatIdMapping slice, `nse_inbox_removal` when inbox-role, §A3 cursor reset incl. `lastKnownHighestModSeq` — CONDSTORE is epoch-scoped; captures rfc→notified for carry-over) → idempotent out-of-txn purges (per-folder FTS helper, NSE staged slices, delivered-notification clears, LAST the BodyAssetStore manifest-QUERY purge — recomputable after a crash, unlike a captured-id list) → fresh-observation stamp via the non-refusing STATUS path, ONE write sets new epoch + reset moment + clears the flag, mirror advances synchronously → resync via `syncFolderMessages` (the account-add path), unread recount, repaints. **PRESERVED: `messageAICache`** (RFC-keyed) — resynced rows re-associate via `restoreIfCached` with zero LLM re-processing (rfc-non-nil; hard-tested) — and PendingOperation rows (Law 5: the reaction never touches the queue).
4. **Sync-merge collision invariant (§5) + universal in-txn guards (§5.5):** sync NEVER rewrites a non-nil `rfc822MessageId` in place. Same (folder, UID) + different rfc → epoch-mismatch fires the reaction and aborts the folder pass; same-epoch is an anomaly (error-logged, identity overwrite refused, non-identity fields merge — one corrupt staged row must never purge a healthy folder). Every un-gated writer (full-sync merge, NSE merge both phases, body persist + envelope-rfc verify, delta cursor persist, backfill chunks, folder-metadata pass) re-reads flag+epoch INSIDE its own write txn — out-of-txn checks are TOCTOU-broken by construction. `handleVanishedUIDs` gains the same epoch guard (a stale pre-reset IDLE session must not delete new-epoch rows by raw UID).

**Riders (Stage 4, from the family audit — defense-in-depth kept despite the root-cause closure):** F1 in-txn snapshot-identity verify inside the action methods' gated txns (the fold-filter→action-txn TOCTOU); F5 staged synthesized dates never captured as identity (false-refusal = dropped intention); F6 RFC pinning at user-label and outbox direct admissions; F7 account-scoped unique-match outbox rfc lookup (live cross-account bug, no epoch needed); F9 refused-ids repaint; D-2 outbox replied/forwarded flags DEFER (in-memory park + re-run at reaction end / foreground) instead of silently skipping when the original's folder is mid-reset.
