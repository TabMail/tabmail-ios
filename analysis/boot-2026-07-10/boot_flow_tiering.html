5 syncStartup — the herd post-paint

A sequential preamble (steps 0–3), then everything runs in parallel — subordinated by TIER, not by scheduling order. The whole stage is concurrent with the UI.

5a — SEQUENTIAL preamble (each step awaited):

Step-0: NSE merge (awaited)staging drains completely BEFORE any sync pass, so sync never races the merge over the same headers
Step-1: cancel stale in-flightonly on genuine resume (oracle-gated) — releases suspension-frozen tasks/connections
Step-2: recover incomplete headerscrash-recovery FTS re-index (headerComplete=0 rows)
Step-3: repopulate ALL queues (detached)active body/AI + backfill body/AI/embeddings + memory — loads work; the queues' own drain loops take it from here
▼ then everything below runs IN PARALLEL, ranked by tier ▼

✓ RESOLVED (ADR-IOS-056, 2026-07-10): the old "5c budgeted body/AI drain" is gone. Write tiers — who writes at which priority

One serial writer; DatabaseWriteQueue schedules by tier (lower wins). A tier can't preempt an in-flight write body — a 3 s priority write still blocks everything behind it.

.priority (0)  jump the queue — user-visible NOW

  • User actions — AccountManager.enqueueWrite FIFO closures (read/flag/tag/move); FIFO order is guaranteed within the user queue, tier order at the DB
  • NSE merge phases — privileged context forces .priority even through re-tiered code paths (phase-1 header upsert, phase-2 body/AI)
  • Badge / unread recounts
  • On-demand user-open body fetch — opening a message that needs its body (live user action; deliberately NOT re-tiered by ADR-IOS-056)

.normal (1)  sync-level steady state

  • Sync engine writes — normalPool/syncPool (header upserts, folder updates, stale deletes)
  • Active body queue flushes — body blob, snippet, bodyComplete/FTS flips (ADR-IOS-056: was .priority)
  • Active AI queue result writes — summary/action/reply, AI cache (ADR-IOS-056: was .background — inbox AI is sync-level, not backfill)
  • Explicit normal { } blocks

.background (2)  yield to everyone

  • Backfill body / AI / embedding queues (backgroundPool) — run in foreground too, just lowest tier
  • Bulk maintenance (asset eviction, prunes)
Read paths, for contrast: dbPool.read async = merge-gated (awaits mergeIfStagingPending first); dbPool.read sync = passthrough; rawPool.read = raw, no gate — the repaint-critical paths (InboxListReader.fetch, flushAIBatch, snippets) all use rawPool so a slow merge can never block a repaint.
